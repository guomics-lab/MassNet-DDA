# 安全边界复核与加固说明

复核基线：`12ecd7521d3e4d304e6ab74bc132b8a9ef763151`。日期：2026-09-23。本说明只涉及本次安全加固，不评价模型科学性能或发布数据质量。

本项目主要是本地科研命令行程序。未发现主程序提供公网上传服务；下列问题不能统称为无需交互的远程入侵。复核采用源码追踪、临时目录测试、真实小型数据库以及无副作用的内存标记，没有攻击线上服务或读取真实凭据。

## 复核结论与本次变更

| 原问题 | 反证复核后的判断 | 本次处理 |
|---|---|---|
| S-01：索引对象反序列化 | 保留：读取外部既有索引时可执行其对象还原函数。真实数据库和正常元数据可到达。前提是用户选择或缓存被替换为不可信索引 | 用带版本、大小限制及字段校验的纯数据记录替换对象序列化；旧格式在读取记录前拒绝，重建索引 |
| S-02：检查点加载 | 保留为明确的可信文件边界，不能称为本项目新发现的框架漏洞；旧框架本来允许对象执行，正式下载器已有摘要保护 | 正式评估、预测、微调和恢复训练均验证官方摘要或调用者明确提供的可信摘要；校验私有副本并加载该副本；测试下载复用发布摘要 |
| S-03：凭据写入运行产物 | 保留：完整配置和带认证信息的远程地址会落入日志、元数据与导出配置；合成凭据复现 | 统一递归脱敏；地址移除认证、查询及片段；保留运行中的原配置 |
| S-04：构建归档越界写入 | 保留路径写入缺陷，降低为构建供应链加固；攻击者若已控制会被编译的源归档，本来就拥有严重供应链能力 | 提取前检查全部成员；拒绝路径穿越、链接、特殊文件及超限归档，在私有暂存目录写入后发布 |
| S-05：固定形状原生核 | 保留条件性边界缺陷。短时间步数组存在具体可达的越界读取路径；默认形状未据此判为越界。没有设备利用实证 | 开启质量控制时限制支持的长度、词表及质量映射；内核启动前检查形状、有限值与资源预算 |
| S-06：质量驱动资源分配 | 降级为输入预算与服务化加固项；当前没有证明公网拒绝服务入口 | 限制主要质量网格工作数组的预算、有界工作池、串行化原生工作区使用并传播工作异常 |
| S-07：尾线程检查次序 | 降级为防御性原生加固；编译器可能优化掉无效读取，且原训练入口另有未定义名称问题 | 将已有样本边界退出移到索引读取之前，保持退出线程集合不变；设备内存及同步验证仍未完成 |

索引文件名可没有扩展名。原文件选择函数未使用扩展名列表不单独计为安全漏洞；后缀不是反序列化信任边界。本次没有为了“修漏洞”破坏合法无后缀索引入口。

## 兼容性与使用说明

### 索引

新建索引包含记录格式版本，数值与字符串以 JSON（JavaScript Object Notation，JavaScript 对象表示法）保存，不调用 `pickle.loads`。旧的对象序列化索引默认拒绝，请保留原始峰文件并重新生成索引；不提供在主运行环境中自动解包旧对象的迁移后门。不要覆盖唯一的旧数据副本。正常峰文件输入仍使用原解析流程，索引名称无需后缀。

每条记录限制为 16 MiB（Mebibyte，二进制兆字节）、250000 个峰，并检查数组等长、有限数值、电荷范围和注释长度。这是存储层边界，不意味着模型支持范围扩大到这些上限，也不保证整个文件的内存占用已受限。

### 模型检查点

官方已发布的两个检查点摘要沿用 `download_data.py` 中的值。自训练或其他受信检查点需显式给出摘要：

```sh
python -m XuanjiNovo.XuanjiNovo --mode denovo --model trusted-model.ckpt \
  --peak_path sample.mgf --trusted-checkpoint-sha256 <trusted-publisher-sha256>
```

尖括号位置替换为可信来源确认的摘要。SHA-256（Secure Hash Algorithm 256-bit，256 位安全散列算法）只标识文件；对一个不可信文件自行计算摘要再批准，**不会使其中的可执行对象变安全**。程序接口的 `predict`、`evaluate`、`train` 也增加可选参数 `trusted_checkpoint_sha256`；该授权值不从检查点或配置文件自动获取。

加载前按流复制并核验，框架只读取私有暂存副本，防止源路径在核验后被替换；最大检查点大小为 16 GiB（Gibibyte，二进制吉字节）。暂存需要额外磁盘和复制时间；恢复训练时副本保留至该次恢复调用结束。

这是一项来源审批和完整性加固，**仍然不支持安全加载任意不可信旧检查点**。直接调用底层框架加载函数也不受命令行边界保护。数据专用权重格式迁移、框架版本升级和完整模型数值兼容性测试属于后续工作。

### 配置导出

配置记录、快照和保存文件中的凭据被替换为脱敏标记，认证必须重新注入。普通参数保留，正在使用的原始配置不被修改。敏感键递归识别，并清理结构化地址；不得把任意自由文本当作保密凭据存储。日志脱敏不是对所有第三方库日志的全面防泄漏保证。

### 构建归档

安全提取不执行归档中的链接或保留其所有者／危险权限。不覆盖既有提取目录。已有本地构建树仍属可信构建输入，应使用干净工作区；这次没有声称给上游归档增加来源真实性证明。需要维护者核实并固定可信归档摘要。链接或非常规布局会被拒绝，真实上游完整构建仍需验证。

### 原生解码

PMC（Precise Mass Control，精确质量控制）当前原生实现固定支持 40 个时间步和包含空白符在内的 28 个类别。其他长度／词表需关闭 PMC，或在后续实现与验证动态内核；本次不扩大算法能力，也不改变其化学常数约定。主要四个网格数组每次限制为 64 MiB，实际总显存还包括模型、概率及分配器缓存；预算不等于进程总显存上限。

## 验证范围与剩余限制

新增回归套件可独立运行：

```sh
python -m pip install numpy==2.2.6 lmdb==1.7.5
python -m unittest discover -s tests/security -p 'test_*.py' -v
```

上述固定测试依赖用于 Python 3.10／3.12 的持续集成环境。LMDB（Lightning Memory-Mapped Database，闪电内存映射数据库）测试使用真实小数据库，索引写入使用合成解析结果，并将映射大小调低；测试不执行真实峰文件解析。元数据和配置导出测试执行原函数，对硬件查询及部分序列化依赖采用替身。归档、凭据和检查点测试只用合成数据。模型检查点测试替换框架加载器，不执行对象检查点。原生边界测试验证启动前约束和源码检查次序，不等于执行显卡内核。

本地实际结果：43 项测试在 Python 3.12.14 与 Python 3.14.6 上均通过；其中 Python 3.12.14 使用 NumPy（Numerical Python，数值计算库）2.2.6、LMDB 1.7.5。测试覆盖 Windows 保留文件名、含特殊字符的地址凭据和源检查点在校验后被替换等边界。Python 3.10 的运行结果以新增持续集成任务为准，不能由本地结果推定。

新增独立 CI（Continuous Integration，持续集成）只运行安全套件，不依赖网络模型下载和显卡。原仓库已有工作流、完整模型训练、CUDA（Compute Unified Device Architecture，统一计算设备架构）编译、设备内存／同步检查和吞吐回归仍须另行验证。

多节点恢复训练也未完成集成验证；私有暂存检查点路径在不同节点上的可见性和生命周期须另行核实，本次不宣称该部署方式已受支持或验证。

本次没有批量升级深度学习运行栈，避免把未经兼容性验证的大规模版本迁移伪装成已完成修补。复核确认的官方公告包括：

- PyTorch（深度学习框架）[CVE-2026-24747 公告](https://github.com/pytorch/pytorch/security/advisories/GHSA-63cw-57p8-fm3p)：所述受限加载问题影响至 2.9.1，修复从 2.10.0 起；不能只给旧版增加“仅权重”参数就保证安全。
- urllib3（网络请求底层库）[2026-09-15 公告](https://github.com/urllib3/urllib3/security/advisories/GHSA-vxq7-64xx-v4gw)：流式分块响应问题修复从 2.8.0 起；本项目相关风险仍需升级兼容网络栈后处理。
- Requests（网络请求库）[代理重定向公告](https://github.com/psf/requests/security/advisories/GHSA-j8r2-6x86-q33q)：依赖代理认证和特定重定向条件，相关修复从 2.31.0 起。

CVE = Common Vulnerabilities and Exposures，通用漏洞与披露；GHSA = GitHub Security Advisory，GitHub 安全公告。上述版本是对应公告的修复下限，不是“全部漏洞清零”的保证。未在本次测试中改变网络代理或利用官方下载服务器。

该变更是有范围的安全加固，不能表示系统已完全安全或所有历史审计条目均已根治。全模型和设备验证完成前适合按草稿拉取请求审阅。
